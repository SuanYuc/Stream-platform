046 [] 三、背景技术（现有技术）
047 [] 3-1找出最接近的现有技术
048 [] 近些年来的虚拟现实技术蓬勃发展，相关的工具也在不断完善。例如，Unity引擎作为全球领先的实时3D开发平台，可以提供强大的渲染能力以及 灵活的脚本支持，开发者能够高效地构建复杂的虚拟场景，搭配官方制作维护的 AR Foundation 插件，能够轻松构建 AR/XR 应用。此外，Unreal Engine 以其逼真的图形效 果和高效的物理引擎，也在虚拟制作领域占据重要地位。这些工具的出现，不仅降低了 虚拟演播室开发的技术门槛，还为创作者提供了更多的可能性。例如，通过使用这些引擎，创作者可以轻松实现动态光影、实时特效和复杂的场景交互，从而提升节目的视觉 效果和互动性。
049 [] 同时，人工智能技术的进步也为虚拟演播室带来了新的机遇。例如，基于深度学习的图像处理技术可以实现高质量的实时抠像，使得虚拟场景与现实视频的融合更加自然。此外，自然语言处理技术可以用于实时字幕生成，提高节目制作的效率。这些技术的应 用，能够提升节目的制作质量，还能够为观众带来更加沉浸式的观看体验，给观众带来 了前所未有的视觉冲击。
050 [] 3-2  要解决的技术问题
051 [] 当前，虚拟综艺演播厅的研究已经进入较为成熟的阶段，国内外学者和技术开发者在虚拟环境创建、语音合成、人机交互等方面取得了显著的进展。2022 年，工业和信息化部等联合印发《虚拟现实与行业应用融合发展行动计划（2022—2026 年）》 白皮书明确提出要提升我国虚拟现实产业核心技术创新能力，激发产业服务体系创新活力并加快虚拟现实与行业应用融合发展以构建完善虚拟现实产业创新发展生态。
052 [] 然而，现有虚拟综艺演播厅系统仍存在以下技术瓶颈：
053 [] 传统绿幕技术存在严重的物理空间限制，需要专门的摄影棚和大量物理空间，设备成本高昂，包括绿幕、灯光设备、摄影棚租赁等费用巨大。同时，绿幕拍摄灵活性差，受限于绿幕背景，无法实现复杂场景切换，后期制作复杂，需要大量人工后期处理，效率低下。
054 [] 现有技术难以高质量重建大范围真实场景，三维建模效率低，手工建模耗时耗力，成本高昂。传统虚拟演播室场景切换需要重新搭建，缺乏灵活性和实时性，无法满足现代综艺节目快速制作的需求。
055 [] 实时交互和智能化程度不足，传统演播室需要大量人工操作和协调，操作繁琐且效率低下。场景切换、特效添加等操作无法实时完成，缺乏AI辅助的自动化制作流程，智能化程度严重不足，无法适应现代综艺节目的制作需求。
056 [] 语音识别和字幕生成问题：传统综艺节目缺乏实时字幕，严重影响无障碍体验，特别是在嘈杂的综艺节目环境下，语音识别准确率低，后期字幕制作耗时，人工制作字幕成本高、周期长，无法满足现代观众的观看需求。
057 [] 因此，在虚拟综艺演播厅系统中通过研究高斯重建算法、ORB_SLAM3实时相机路径追踪、RobustVideoMatting无绿幕抠像技术、ncnn语音识别系统等关键技术，可为虚拟综艺演播厅从技术验证阶段向实践应用阶段的转化提供坚实的理论与方法支撑。

062 [] （2）实现基于AI的虚拟综艺演播室系统：使用人工智能技术，突破传统绿幕限制、实现全离线语音识别智能化制作流程升级。无绿幕抠像技术采用RobustVideoMatting（RVM）抠图模型，实现人物前景与背景的高精度分离；集成ncnn 语音识别系统，语音识别技术生成字幕，助力综艺节目的无障碍化体验。
063 [] 五、有益效果
064 [] 本发明的有益效果为：首先，通过无绿幕抠像技术和虚拟场景重建，系统摆脱了传统绿幕对物理空间的依赖，大幅降低了摄影棚租赁、绿幕设备、灯光系统等硬件成本。其次，基于AI的场景重建技术实现了大范围真实场景的快速高质量重建，相比传统手工建模效率提升数倍，大幅提升制作效率。第三，集成ncnn语音识别系统实现实时字幕生成，有效降低后期字幕制作成本，为观众提供更好的观看体验。这些创新成果为传统媒体机构的数字化转型提供了完整解决方案，使中小型机构也能以较低成本快速建立现代化综艺制作能力，推动了AI技术在媒体领域的深度应用和产业化进程。

066 [] 七、具体实施方式
067 [] 本发明涉及一种基于AI大模型的智能化虚拟综艺演播室。包括以下步骤：
068 [] 1.虚拟综艺演播室系统的搭建：
069 [] 该部分分为3个小节。场景搭建这一节中讲述了如何使用高斯溅射和Meshroom 重建三维模型，并将其导入到 Unity 中作为虚拟场景使用。摄像机路径跟踪这一节分为了离线追踪和实时追踪部分：离线追踪将会详细阐述如何利用上一章提到的 ORB_SLAM3 算法进行摄像机路径追踪，实时追踪将会解释Unity如何引入AR插件，实现虚拟摄像机的即时移动。辅助功能这一节将会阐述完善虚拟综艺演播室的辅助系统，例如场景自由编辑和灯光控制等。
070 [] 场景搭建
071 [] 场景搭建是虚拟综艺演播室的重要功能之一，该系统支持大范围的三维场景重建以及小范围的三维物体重建。在大范围场景重建部分我们将会详细阐述如何使用高斯溅射 进行大范围的场景重建，包括如何通过Colmap生成每张照片对应摄像机的位姿信息、如何利用这些位姿信息构建高斯溅射场景。在小范围物体重建部分我们将会解释如何使用Meshroom 重建小物体模型，并且利用Blender 和 Unity 插件来优化重建完成的小物体模型，使系统保持良好的性能状态。
072 [] 1.1.1大范围场景重建
073 [] 使用高斯溅射工具3DGS，实现对大范围场景的重建。部署官方项目后，还需要依次安装四个依赖环境：Anaconda、Visual Studio 2019、CUDA 11.8 和 Colmap，部署成功后开始三维重建。在高斯溅射重建过程中基本的思想是：先提取图片中的特征点，通过这些特征点数 据构建出摄像机的拍摄位置，同时定位特征点在场景中的位置。这一步骤可以使用 Colmap实现。Colmap中构建出的点云和摄像机预览如图 1所示。
074 [] 图1 Colmap 生成点云和摄像机位姿
075 [] 高斯溅射技术通过将预先输入的摄像机参数和稀疏点云数据作为输入，实现精确的 三维场景表示。该方法首先将采集的多视角图像数据和相机位姿信息输入至重建系统， 随后进行迭代优化过程。整个系统将会自动调整三维高斯函数的参数（包括空间位置， 协方差矩阵、颜色属性和不透明度），最终生成包含完整场景几何和外观信息的ply格 式三维模型文件。
076 [] 由于Unity 原生环境缺乏对 ply 格式点云数据的直接支持，本系统基于开源项目 UnityGaussianSplatting 进行开发，构建了适配三维高斯溅射模型的渲染管线。通过利用 该开源项目提供的内置转换工具将其序列化为Unity可识别的二进制资源文件。随后在 场景层级管理器中创建GaussianSplats 实体，将处理完成的资源文件绑定至该实体，实 现ply文件的可视化实现，该方案有效解决了三维高斯溅射模型在游戏引擎中的渲染适 配问题，场景渲染帧率稳定在60fps以上，为后续虚实融合场景的构建奠定了技术基础。 其运行结果如图 2所示：
077 [] 图2 Unity 导入高斯溅射模型
078 [] 为了实现场景的高质量渲染，我们选用了Unity的URP（Universal Render Pipeline）作为渲染管线。URP 是 Unity 于 2019 年提供的可编程渲染管线，相比于之前的内置（Build-in）渲染管线，具有很多的优势。
079 [] URP 对批处理进行了优化，减少了Draw Call，这意味着使用该渲染管线的工程性能更优。此外该渲染管线支持基于物理的渲染（PBR）材质系统，能够提供更加真实和 优质的渲染效果。另外，URP内置了各种后处理效果，如泛光、色彩分级和景深等。通过这些特性，能够为虚拟综艺演播室提供更加真实的渲染效果。
080 [] 1.1.2小范围物体重建
081 [] Meshroom 是一款基于AliceVision 的开源三维重建软件，它能够根据一组照片自动识别环境和摄像机的位置，构建出三维模型。Meshroom 主要基于两大核心算法：运动结构恢复（Structure from Motion, SfM）和多视角立体视觉（Multi-View Stereo, MVS）。整个重建流程可以分为以下步骤：首先是特征提取，Meshroom使用SIFT算法提取 特征点，每个特征点包含位置和描述符信息，用于之后的特征匹配。特征匹配阶段，将 会构建图像间的连接关系，用于估计不同相机之间的位姿。第三阶段为SfM阶段，通过 三角测量法，恢复特征点的三维坐标，同时估计相机的内参和外参。此阶段过后，将会输出稀疏点云。第四阶段为深度图估计，在该阶段，Meshroom将会使用MVS算法估计 每个像素的深度。第五阶段为深度图融合阶段，此时将会输出稠密点云。第六阶段为网格（Mesh）重建阶段，利用泊松表面重建德劳内三角化算法，构建出三维模型。第七阶 段为纹理映射阶段，此阶段将会根据原始图像提取纹理信息，计算每个三角面的UV坐标，最终生成纹理贴图。其重建流程图如图 3。
082 [] 图3 Meshroom三维重建流程图
083 [] Meshroom 重建需要准备一组照片作为数据集。照片拍摄要求需要注意几点：需要 合适分辨率的相机，照片最好能够包含相机型号、参数等信息，Meshroom 需要这些信 息来估计相机的内参和外参。在围绕拍摄物体拍摄时，需要涵盖物体的各个角度，包括 其顶部。拍摄主题和背景需要分离，用纯白色背景拍摄最后重建效果会更好。避免拍摄反光较强的物体和特征点较少的物体。 重建开始前，需要将拍摄完成的照片拖入Meshroom后，发出开始重建指令。在重建过程中，Meshroom 会自动进行特征提取、重建、纹理映射等步骤，最终生成三维模 型。如果出现重建失败的情况，可以尝试调整参数，或者重新拍摄照片。采用Meshroom 重建的时间会比较长，推荐使用支持CUDA的NVIDIA显卡进行重建。
084 [] 如果重建出来的三维模型不理想，可以后期在Blender中进行优化。 Blender 是一款功能强大的开源三维计算机图形软件，支持建模、绑定等全流程三 维创作。Blender 的核心在于全面的功能继承和活跃的社区支持。在模型处理方面， Blender 提供了丰富的工具，包括体素化重构、网格简化和重拓扑等。通过这些工具，我 们能有效地优化三维扫描或摄影测量生成的高面数模型。在本系统中，我们将会使用 Blender 的体素化重构功能，优化Meshroom重建的三维模型。并导出为合适的格式以供 Unity 导入。
085 [] 使用Blender 导入重建完成的模型，准备体素化重构。在体素化重构前，需要对模 型做进一步的处理，包括删除空洞、修复拓扑等。可以使用“合并距离很近的顶点”功 能移除重叠顶点，或使用“填充孔洞”功能修复模型中的小孔。
086 [] 接下来，需要使用Remesh修改器进行体素化减面。在Remesh修改其中可以调整 许多的参数，在这里我们选择"Voxel"作为模式，调整"Voxel Size"参数控制网格密度。 "Scale"参数可以调整整体细节级别。在预览窗口预览效果并调整到合适参数。
087 [] 模型减面会导致UV结构发生变化，此时需要纹理重映射，使用Blender的“智能 UV展开”功能重新调整UV布局后，还需要在材质设置里重新应用原有材质。

091 [] 在优化完成后，需要进一步将模型导出为FBX格式，以供Unity导入。FBX格式 是Unity支持的格式，可以保留模型的拓扑结构和UV信息，同时支持导入动画、材质等信息。
092 [] 在Unity中，我们还可以进一步优化模型的显示，细节层次（Level of Detail，LoD）是一种很好的选择。LoD是一种在不同距离下显示不同细节的优化技术，可以有效降低模型在远处的渲染开销。本次课题选择的LoD插件为开源的UnityMeshSimplifier。通 过该插件，我们能很轻松的生成对应模型的不同细节层次，然后实现LoD显示效果。图 6直观展示了LoD的原理。
093 [] 图 6 LoD示意图
094 [] 在这里我们选用的UnityMeshSimplifier 插件对本课题兼容性良好，还具有许多不错的特性帮助优化。该插件使用的是快速二次网格简化（Fast Quadric Mesh Simplification）算法来生成LoD。其算法使用了二次误差度量（Quadric Error Metrics）来合并顶点。这种算法能够迭代删除网格中影响视觉效果最小的顶点来简化模型，简化过程中保持了模 型的整体形状和视觉特征。
095 [] 该插件还创造性的添加了“智能连接（Smart Linking）”特性，能够预防简化模型中可能会出现的模型坑洞问题，提升了视觉观感。调整不同的LoD数值，会对画面产生不同影响。如果摄像机处于近景时，会转换为 LoD1 级别。优化质量代表模型在此级别下的显示面数，LoD级别越高，优化质量应越小，模型面数越低。通常情况下，我们需要将高级别LoD设置一个合适的画面比重和优化质量，这样就能同时兼顾性能和画面质量。在本课题中我们使用默认LoD设置，优化 我们的模型，其在场景中渲染的参数信息如图7所示：

135 [] 1.3.1绿幕抠图着色器实现
136 [] 着色器（Shader）是一种用于控制物体对象表面外观程序脚本，主要运行在GPU上。 着色器可以控制每一个像素、顶点的颜色、透明度和光照，并进行一定的计算来实现效果。本课题绿幕抠图功能实现依赖于Unity Shader，其目的是实现去除视频画面中的绿色背景，实现真实人物和虚拟场景的融合。
137 [] 绿幕抠图（Chroma Key）是一种广泛应用于影视制作和直播行业的视频处理技术。绿幕抠图通过识别并移除视频中特定颜色（通常为绿色或蓝色）的背景，将前景主体与其他背景合成。绿幕抠图的核心原理是基于颜色空间的分离：首先，将RGB颜色空间转换为YCbCr颜色空间，这种转换能更有效地分离亮度信息（Y）和色度信息（Cb、Cr）。分离亮度信息和色度信息的数学公式如图17：
138 [] 图17 分离亮度信息和色度信息的数学公式
139 [] 其次，在色度平面（Cb-Cr）上计算像素颜色与关键色（绿幕颜色）之间的欧氏距离， 根据距离判断像素是属于前景还是背景。绿幕（通常是纯绿色）在YCbCr空间中有非常 明显的特征，尤其是在Cb和Cr平面上。在Cb-Cr平面上计算欧氏距离时，可以有效区 分绿幕和非绿幕区域，不受亮度变化的干扰。其计算公式如图18所示：

169 [] 2.实现基于AI的虚拟综艺演播室系统
170 [] 使用传统的虚拟综艺演播室制作综艺节目具有很多限制。为了满足现代视频制作对于灵活性的需求，人工智能技术使得无绿幕抠图成为了可能。在本部分的第一小节，将会介绍RobustVideoMatting无绿幕抠图技术，并详细阐释如何将其部署至整个虚拟综艺演播室系统中。 为提升综艺节目的无障碍服务能力，实时语音识别（Automatic Speech Recognition, ASR）技术可以集成于虚拟综艺演播室系统。这项技术能够在综艺节目播出时实时生成字幕，提升了特殊群体的收视体验，更通过AI技术赋能实现了节目制作流程的智能化升级。本部分第二小节将会介绍一种基于 NCNN 的语音识别技术，并将其引入至整个虚拟综艺演播室系统当中。
171 [] 2.1 RVM无绿幕抠图
172 [] RobustVideoMatting（简称 RVM），是由字节跳动研发的一种视频抠图算法，于2021 年发布。该算法专门对人物视频抠图进行优化设计，即使在没有绿幕的情况下，也能实时处理高分辨率视频并保持出色的视频质量。这种抠图方式为虚拟综艺演播室系统提供了更加灵活的人物和背景分离的方式，使得演播室可以在几乎任何环境下拍摄，不再受限于传统的绿幕演播室。
173 [] RVM的基本原理由以下组件组成：第一是编码器部分，RVM使用MobileNetV3或 ResNet50 作为骨干网络提取视频帧的特征，捕捉不同层次的视觉信息。第二是循环模块，RVM 采用循环神经网络处理视频序列，使得该模型能够捕捉视频中的时序信息，从而捕捉视频中的运动特征和时间连贯性。第三是解码器部分，RVM 将时序信息的特征解码为Alpha 通道和前景预测，实现视频的实时抠图。第四是细化模块，RVM 模型还可以处理半透明区域，实现如头发丝的细节方面的抠图。 RVM模型使用的MobileNetV3或ResNet50是广泛应用于计算机视觉人物的深度学习模型，其中 ResNet50 主要用于解决深度学习网络中的梯度消失和网络退化问题。 ResNet50 在ImageNet 等大规模图像分类任务中表现优异，但需要较高精度和计算资源充足的场景。MobileNetV3是谷歌提出的轻量级卷积神经网络，为移动端和嵌入式设备设计，具有较低的计算量和内存消耗，能够实现快速的实时处理。
174 [] 本系统针对的实时视频抠图任务，我们采用了用轻量化深度神经网络架构 MobileNetV3 作为核心算法模型，并且将该模型整合至Unity引擎项目的Assets资源目 录中。为了实现该模型的实时推理功能，本研究设计开发了针对该模型的专用脚本模块，如图27所示，该模块通过使用微软机器学习框架提供的ONNX Runtime推理引擎实现模型的高效部署。

184 [] 2.2基于NCNN的语音识别
185 [] 在虚拟综艺演播室中，语音识别是一项重要的功能。通过语音识别，我们能实现字幕的实时生成，为观众提供更好的观看体验。为了实现语音识别的功能，我们将会使用sherpa-ncnn 语音识别系统。Sherpa-ncnn 是一个开源的轻量级实时语音识别系统，由k2fsa 团队开发。这是一个完全离线的语音识别系统，不需要依赖网络。

260 [] 如图1-8所示，本发明实施例所述的一种面向遥感图像处理算法的快速并行化编程模板方法，包括以下步骤：
261 [] 1)提取三种典型遥感图像并行处理模型：
262 [] 根据算法的重复性计算特点归为三类：像素重复运算、局部区域重复运算、波段间重复运算和全局信息类运算，并提炼出三种较为典型的并行计算模型，包括纯数据并行模型、波段相关数据并行模型、全局信息计算并行模型。
263 [] 纯数据并行模型：主要针对具有局部区域重复计算性的算法，其输出图像可由输入图像中某个像素或局部区域内像素的独立运算得到，适合图像运算，辐射/几何校正，图像增强等算法。该模型的并行处理流程如图3。主节点完成参数获取、结果图像范围计算、数据/计算任务划分及节点间计算任务动态调度；从节点不断从主节点获取子任务，并进入由I/O数据读取、多个核心处理算法功能、数据输出操作等组成的多级流水线中，流水线各级映射到多个线程中执行，各线程通过共享环形缓冲区(buffer)在内存空间交换数据。该模型中利用多线程技术充分发挥内核线程级并行，且使用数据预取策略，使I/O与计算充分重叠。
264 [] 波段相关数据并行模型：主要针对具有波段间重复计算特性的算法，既输出图像的某像素或区域的计算由多个波段的共轭点或区域共同参与运算。这类算法的数据并行性和计算的数据局部性也较好。适合图像变换、图像融合、波段配准等算法。该并行模型也采用任务池并行主要并行处理流程与纯数据并行模型大体相同，区别在于任务划分时与波段数无关，在核心模块处理数据块时中多个波段对应的数据块一起参与计算。
265 [] 全局信息计算并行模型：针对信息计算类遥感算法，并行计算流程中间或结尾中涉及全局计算，如：图像分类、直方图规定化等。全局信息计算并行模型的并行处理流程如图4，主节点完成参数获取、数据/计算任务划分、节点间的计算任务动态调度；从节点循环从主节点获取子任务，并进入由I/O数据读取、多个核心处理算法功能、计算结果回收等组成的多级流水线中，流水线各级并发执行；完毕后，所有计算节点同步对回收的计算结果进行全局处理；最后若无随后的计算处理则整个计算流程结束，否则，则启动另一个流水线处理阶段，最终输出计算结果信息或者结果图像数据。
266 [] 2)构建并行编程模板库：
267 [] 该并行编程模板库的模板类设计如图5所示。编程模板中抽象了一个编程模板父类ImgProcessingParallel，数据类型ProcessingParam负责算法基本参数和私有参数的管理。通过对以上三种并行处理模型进行接口抽象设计，并继承模板父类，得到纯数据并行编程模板类ImgProcessingDataParallel，波段相关数据并行编程模板类ImgProcessingBandRelatedParallel和全局信息计算并行编程模板类ImgProcessingGlobalParallelNoImg。

269 [] 3)继承并行编程模板类：
270 [] 通过继承编程模板库中的并行编程模板类，即可加载指定的遥感图像并行处理模型，从而实现遥感处理算法的快速并行化，其具体快速并行化实施流程如图7所示。
271 [] 首先，要根据具体算法明确提出所需的外部参数，这些参数包括被处理对象的输入输出结果路径、图像大小，以及其他需要从外部传入的参数等，并行程序完成后系统将自动根据这些参数生成为该并行算法生成XML参数文件。其次，根据经验选定需要继承的并行模板类。再次，按图8中的并行算法主程序的程序目录结构构建和编写用户程序，并在ImgProcessingParallelImp.h中申明要使用的并行编程模板，即实现类ImgProcessingParallelImp继承选定的编程模板类。而后，加载用户核心功能函数，即在ImgProcessingParallelImp.cpp中重载BlockProcessing方法，并在该方法中调用用户编写的串行核心算法功能函数。最后，进行联合编译、执行。遵循这一流程即可快速实现一个并行效率较高的并行处理算法。
272 [] 若用户算法需要继承全局信息计算并行编程模板类，则还需要重载全局计算(GlobalComputing)，加载用户自定义的全局计算算法。若用户需要进一步提高并行效率，则可以重载SplitDesImage操作接口或LoadBalance操作接口，调用自定义的数据任务划分和负载均策略。
